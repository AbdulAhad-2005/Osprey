# Arsenal tooling gap

Tools referenced by `requires_tools:` in `skills/` that are not yet installed in
`kali-tools/Dockerfile` / listed in `config/kali_allowlist.json`. Generated by
`python scripts/lint_skills.py`'s WARN report — treat that command as the live source of truth;
this file is the install-recipe companion to it, updated as each phase's skills are written.

Skills are written ahead of tooling by design (per project decision) — a skill with
`requires_tools` not yet here is real, correct content that goes live the moment its tool lands.

## Active Directory (`skills/active-directory/phase-overview.md`)

All of these are the standard AD-testing toolchain — none ship in Kali's base install; all are
pip/pipx/go installable. Add to `kali-tools/Dockerfile` section 4b (pipx-isolated tools, same
pattern as `maigret`/`sslyze`/`prowler`) and section 3 (Go tools):

```dockerfile
# ─── AD toolchain (pipx-isolated, same pattern as maigret/holehe/sslyze above) ───
RUN --mount=type=cache,target=/root/.cache/pip \
    pipx install impacket \
    && pipx install netexec \
    && pipx install certipy-ad \
    && pipx install bloodhound-ce \
    && pipx install coercer \
    && pipx install bloodyAD \
    && pipx install ldapdomaindump

RUN --mount=type=cache,target=/opt/go/pkg/mod --mount=type=cache,target=/root/.cache/go-build \
    go install github.com/ropnop/kerbrute@latest

RUN --mount=type=cache,target=/var/cache/apt,sharing=locked \
    --mount=type=cache,target=/var/lib/apt/lists,sharing=locked \
    /usr/local/bin/apt-install-retry.sh 5 ldap-utils krb5-user
```

`config/kali_allowlist.json` — add to `binaries`:
```json
"impacket-secretsdump", "impacket-ntlmrelayx", "impacket-GetNPUsers",
"certipy", "bloodhound-ce-python", "coercer", "bloodyAD", "ldapdomaindump", "kerbrute"
```
(`impacket-GetUserSPNs`, `impacket-GetNPUsers`, `netexec` are already allowlisted — the
Dockerfile just never installed them. `bloodhound-python` is already allowlisted but is the
**old** BloodHound (deprecated collector) — `bloodhound-ce` above is the current one; keep both
allowlisted since some environments still run legacy BloodHound.)

**Note — Windows-side tooling** (Rubeus, Certify, PowerView, mimikatz, SharpHound.exe): these
have no Linux equivalent and are meant to run *on a compromised Windows host*, not in the Kali
container. The skill's Linux/Python equivalents above (impacket, Certipy, `bloodhound-ce-python`)
cover the same techniques from the attacker's Linux operator box; document-only, no install
needed here.

## privesc (`skills/privesc/phase-overview.md`)

PEASS-ng ships as hosted scripts, not a packaged binary — download at build time into a fixed
path so `platform_shell`/`platform_script` can reference it by a stable location:

```dockerfile
RUN mkdir -p /opt/peass \
    && wget -q --tries=5 --waitretry=5 -O /opt/peass/linpeas.sh \
       https://github.com/peass-ng/PEASS-ng/releases/latest/download/linpeas.sh \
    && wget -q --tries=5 --waitretry=5 -O /opt/peass/winPEAS.exe \
       https://github.com/peass-ng/PEASS-ng/releases/latest/download/winPEASx64.exe \
    && chmod +x /opt/peass/linpeas.sh \
    && retry-cmd 5 sh -c 'rm -rf /opt/pspy && git clone --depth 1 https://github.com/DominicBreuker/pspy.git /opt/pspy' \
    && retry-cmd 5 sh -c 'rm -rf /opt/les && git clone --depth 1 https://github.com/The-Z-Labs/linux-exploit-suggester.git /opt/les'
```
`config/kali_allowlist.json` — these run as scripts dropped on the target, not local binaries
invoked from the operator box, so they don't need an allowlist entry the way a CLI tool does;
reference the fixed `/opt/peass/...` paths directly in `requires_tools` documentation instead.

## lateral-movement (`skills/lateral-movement/phase-overview.md`)

```dockerfile
ARG CHISEL_VERSION=""
RUN set -eux; CH_URL="$(python3 /usr/local/bin/gh-latest-asset.py jpillora/chisel '*linux_amd64.gz' "$CHISEL_VERSION")"; \
    wget -q -O /tmp/chisel.gz "$CH_URL"; gunzip /tmp/chisel.gz; install -m 0755 /tmp/chisel /usr/local/bin/chisel

ARG LIGOLO_VERSION=""
RUN set -eux; LG_URL="$(python3 /usr/local/bin/gh-latest-asset.py nicocha30/ligolo-ng '*agent_*linux_amd64.tar.gz' "$LIGOLO_VERSION")"; \
    wget -q -O /tmp/ligolo.tar.gz "$LG_URL"; tar -xzf /tmp/ligolo.tar.gz -C /usr/local/bin agent; mv /usr/local/bin/agent /usr/local/bin/ligolo-agent

RUN gem install evil-winrm
```
`config/kali_allowlist.json` — add `"chisel", "ligolo-agent", "evil-winrm"`.

## persistence / defense-evasion / exfiltration / post-exploitation

No `requires_tools` declared on any of these four skills — every technique they describe runs on
tools already present (`cron`, `reg`, `schtasks`, `curl`, `dig`, standard shell built-ins) via
`platform_shell`/`platform_script`, or is Windows-native tooling with no Linux-side install (the
skills note this explicitly where it applies). Nothing to add here.

## C2 (deliberately out of scope)

Real C2 infrastructure (Sliver/Havoc — team server + listeners + redirectors) is heavy
infrastructure, not a single-container tool install, and is a separate architecture decision from
the rest of this arsenal. `metasploit_run` already covers a basic post-exploitation module
handler for now; revisit C2 as its own scoped decision if the platform's use case grows to need
persistent multi-session handling beyond what Metasploit's handler provides.
