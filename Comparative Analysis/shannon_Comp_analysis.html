1.2 How It Differs From MCP Servers

This is critically important to understand: Shannon is an OpenCode plugin, not an MCP server.

DimensionOpenCode Plugin (Shannon)MCP Server (Darkmoon/HexStrike/pentestMCP)
Integration pointOpenCode plugin API (tool(), hooks)MCP protocol (JSON-RPC over stdio)
Runs asIn-process within OpenCodeSeparate process, stdio communication
Tool definitionTypeScript functions with @opencode-ai/pluginPython FastMCP decorators or JS MCP SDK
System promptInjected via experimental.chat.system.transform hookNot applicable (AI is external)
Pre/post hookstool.execute.before/after hooks for authorization, trackingNot supported (stateless MCP)
Multi-agent methodologyBuilt into system prompt (OMO: Sisyphus, Oracle, Librarian, Prometheus)Only Darkmoon has multi-agent; others have none
Docker managementPlugin starts/stops Docker containerContainer runs MCP server (always up)
Provider agnosticUses whatever LLM OpenCode is configured withDarkmoon has own OpenCode or requires external AI
AuthorizationBuilt-in authorization check before exploitationNone (Darkmoon has MCP gatekeeper)

3. Architecture: Strengths & Weaknesses

STRENGTH

Deepest Web App Testing Methodology

The 600+ line system prompt is the most comprehensive pentest methodology of any tool. Covers SQLi, NoSQLi, XSS (reflected/stored/DOM), XXE, SSRF, YAML injection, IDOR (manual + auto), privilege escalation, file upload (extension bypass, XXE via SVG, YAML bomb), business logic flaws (price manipulation, race conditions), JWT analysis, OAuth/SSO, session management.

STRENGTH

OMO Multi-Agent Framework

Unique Sisyphus→Oracle→Librarian→Prometheus agent framework. Sisyphus executes scans, Oracle does deep white-box review of high-severity findings, Librarian researches CVEs for detected versions, Prometheus strategies phases. This is a genuine agentic structure embedded in the system prompt.

STRENGTH

Smart Hook System

4 hooks: authorization (blocks exploit without consent), progress tracking (real-time logging), session management (persistent auth across tools), and severity escalation (version detection → Librarian, high-severity → Oracle). Hooks make the plugin adaptive and safe.

STRENGTH

Built-in OWASP/CWE/CVSS Database

The report tool (634 lines) includes a built-in vulnerability database mapping 20+ vulnerability types to OWASP Top 10 (2021), CWE IDs, CVSS 3.1 scores + vectors, and detailed remediation. This is not a lookup against an external API — it's compiled directly into the plugin.

STRENGTH

Browser-Based SPA Testing

Playwright + Chromium in Docker enables real browser testing of JavaScript-heavy SPAs. Tests DOM XSS, client-side storage, auth flows, screenshot evidence. Only Darkmoon (headless-browser agent) and Shannon have this capability.

STRENGTH

Auth Session Management

Persistent auth sessions (JWT, cookie, header) across the entire pentest lifecycle. Create sessions, reuse across IDOR/injection/priv-esc tests, generate auth headers. Unique among all four tools.

WEAKNESS

OpenCode Plugin Only — Not Standalone

Cannot run independently. Requires OpenCode >= 1.0.150. Cannot be called from Cursor, Claude Code, or other MCP clients. This limits its portability vs. Darkmoon (standalone Docker stack) or pentestMCP (any MCP client).

WEAKNESS

No Built-in AD Pentesting

Unlike Darkmoon (60+ impacket scripts) and pentestMCP (18 AD tools), Shannon has zero AD-specific tools. The Docker container is Kali-based and could run impacket if installed, but there are no dedicated tools or methodology for AD attacks.

WEAKNESS

No K8s Pentesting

No kubectl, kubeletctl, or kubescape. Unlike Darkmoon, Shannon cannot audit Kubernetes clusters. The Docker container could have these tools added, but they are not present in the current Dockerfile.

WEAKNESS

No Binary Exploitation

No Ghidra, GDB, ROPgadget, Pwntools, or reverse engineering capabilities. Same gap as Darkmoon and pentestMCP; only HexStrike covers this.

WEAKNESS

Tools Are Thin Docker Wrappers

Core tools (recon, vuln_discovery, exploit) simply wrap docker exec with a formatted output. No structured output parsing, no result correlation, no state management. Compare to pentestMCP's structured Finding/ScanState objects or Darkmoon's dashboard push.

MIXED

Tool Depth Is Uneven

Some tools are very deep: report (634 lines, full OWASP/CWE/CVSS DB), js_analyze (477 lines, comprehensive JS analysis), crawler (404 lines), rate_limit (383 lines). Others are thin wrappers: recon (48 lines), vuln_discovery (46 lines), exploit (46 lines). The specialized tools (browser, idor, upload) are solid but the "phase" tools are minimal.

4. Pentesting Performance: Strengths & Weaknesses

STRENGTH

Best Web App Methodology Depth

The embedded methodology covers more attack types than any other tool: SQLi + NoSQLi + XSS (3 types) + XXE + SSRF + YAML injection + IDOR (auto/manual) + privilege escalation + file upload (extension, content-type, XXE via SVG, YAML bomb) + business logic + JWT + OAuth/SSO + account enumeration + security headers + CORS + rate limiting + timing attacks + race conditions + session fixation.

STRENGTH

JavaScript Static Analysis

477-line JS analyzer detects: API keys (AWS, Google, GitHub, Stripe, Firebase, Slack, PayPal), hardcoded credentials, XSS sinks (innerHTML, eval, document.write, dangerouslySetInnerHTML), API endpoints, interesting comments (TODO, FIXME, SECURITY, HACK), file paths. Only Shannon has dedicated JS analysis.

STRENGTH

Rate Limit / Timing / Race Testing

383-line rate limit tool with 3 modes: burst (rapid requests to detect lockout), timing (response time comparison for user enumeration), race (concurrent requests for race conditions). Only Shannon has this dedicated tool.

STRENGTH

Professional Report Generation

Built-in mapping of 20+ vulnerability types to OWASP Top 10 (2021), CWE IDs, CVSS 3.1 base scores + vectors, and remediation. Output in markdown, JSON, HTML, or PDF (via weasyprint). This is more structured than any other tool's report output.

WEAKNESS

No AD Pentesting

Zero AD tools. Cannot do Kerberoasting, AS-REP roasting, DCSync, BloodHound, or any AD attack. Compare: Darkmoon has 60+ impacket tools, pentestMCP has 18 AD tools. This is Shannon's biggest gap.

WEAKNESS

No K8s Pentesting

Cannot audit Kubernetes clusters. Darkmoon dominates here with kubectl + kubeletctl + kubescape + structured workflow.

WEAKNESS

No CMS-Specific Tools

No wpscan, cmseek, or CMS-specific methodology. Darkmoon has 6 CMS agents and wpscan + cmseek installed. The Dockerfile doesn't include wpscan.

WEAKNESS

No Structured State/Findings Management

Unlike pentestMCP (Finding/ScanState/Credential objects with JSON persistence) and Darkmoon (dashboard with findings + infra nodes + campaigns), Shannon has no structured state management. Findings exist only in the AI's context window and the report output.

WEAKNESS

Docker Image Is Large (4.41GB)

Significant download for a Docker image. And many Kali tools (Metasploit, aircrack-ng, etc.) are not actually installed despite claiming "600+ tools" — the Dockerfile installs a curated subset.

6.2 Key Gaps to Fill

CRITICAL GAP

Active Directory

No impacket, no BloodHound, no Kerberos attacks. The methodology mentions AD exploitation (DCSync, Kerberoasting, etc.) but there are no actual tools to perform these attacks. The Kali Docker image would need impacket installed.

Fix: Add impacket, bloodhound-python to the Dockerfile. Optionally create AD-specific tools (ad_dcsync, ad_kerberoast, etc.) wrapping the Docker commands.

GAP

Structured Findings / State Management

All findings exist only in the AI's context window. There is no persistence layer, no structured finding objects, and no cross-tool correlation. If OpenCode resets, all findings are lost.

Fix: Add a findings database (SQLite or JSON store) with reporting capabilities beyond the single report generation call.

GAP

Local Execution (No Docker)

Docker-only execution adds latency (~200-500ms per call) and dependency. For quick checks, users should have an option to run tools locally when available.

Fix: Add a local execution mode that falls through to the system-installed tool if present, with Docker as fallback.

GAP

Advanced Recon Placeholders

shannon_logic_audit (27 lines) and shannon_cloud_recon (27 lines) are empty placeholders that only suggest manual tests, with no actual tool integration.

Fix: Either remove them or implement real scanning logic using available tools (e.g., curl for cloud metadata endpoints, Python for state machine analysis).

9. Conclusion

Shannon Plugin is uniquely positioned as an OpenCode-native penetration testing plugin with the deepest web application methodology and the best reporting engine of all four tools analyzed. Its OMO multi-agent framework (Sisyphus/Oracle/Librarian/Prometheus) embedded in the system prompt gives it genuine agentic capabilities that go beyond simple tool wrapping.

However, it has critical gaps — most notably no Active Directory, no Kubernetes, no CMS tools, and no binary exploitation capabilities. It is also tied exclusively to the OpenCode platform and cannot be used with standard MCP clients like Cursor or Claude Code.

Overall Score: 6.5/10 — Strong web app methodology, excellent JS analysis/reporting, but too many domain gaps to compete with Darkmoon's breadth.

BEST FOR: Web application pentesters who use OpenCode and need deep OWASP Top 10 coverage with professional reports. Also excellent for bug bounty hunters who need methodical SPA/DOM testing, rate limit analysis, and IDOR automation.
